# Changelog

## 3.5.0-m1.4 — 2026-08-13

### Added

- Cognito user pool and app client per environment;
- API Gateway Cognito authorizer for protected routes;
- claim-derived authenticated principals and hard-gated local/test debug identity;
- durable tenant memberships with viewer/editor/admin/owner roles and suspension state;
- server-side tenant role authorization where `X-Tenant-ID` is selector only;
- automatic owner membership on tenant creation;
- membership management and authenticated identity endpoints;
- durable tenant audit trail with transactional writes in SQLite and DynamoDB;
- threat model, abuse cases, and identity/authorization documentation;
- CycloneDX dependency SBOM and deterministic supply-chain evidence checksum ledger;
- authorization/security regression tests for outsider, role ceiling, suspension, audit, and local-identity boundaries.

### Changed

- public contract version raised additively to `1.3.0`;
- application version raised to `3.5.0-m1.4`;
- SQLite schema ledger advanced to migration 2;
- CORS now accepts `Authorization` rather than the removed `X-API-Key`;
- release artifacts include supply-chain evidence;
- deployment profiles control Cognito self-registration: dev on, staging/production off.

### Security

- removed the M1.3 application API-key and Secrets Manager authentication path;
- removed obsolete Secrets Manager permissions from the CloudFormation execution role;
- unrelated authenticated users cannot confirm tenant existence;
- admins cannot grant/manage admin or owner roles;
- suspended memberships are denied on every tenant-scoped request;
- production Cognito deletion protection is enabled and user pools are retained;
- optional software-token MFA, token revocation, password policy, and user-existence suppression are configured.

## 3.4.0-m1.3 — 2026-08-01

### Added

- isolated dev, staging, and production CloudFormation environments;
- environment-specific API stages, Lambda names, concurrency, logs, alarms, and table controls;
- Secrets Manager-generated application API keys with cached, fail-closed retrieval;
- liveness and readiness endpoints with release and Git metadata;
- GitHub OIDC bootstrap infrastructure and temporary-credential workflows;
- containerized arm64 SAM builds;
- build-once tagged release promotion from staging to production;
- controlled deployment and rollback scripts;
- automatic CloudFormation rollback, optional CodeDeploy canaries, and post-deployment smoke tests;
- Dependabot configuration and environment/deployment invariant tests;
- CI/CD, environment, rollback, and operational documentation.

### Changed

- public contract version raised additively to `1.2.0`;
- application version raised to `3.4.0-m1.3`;
- direct and transitive runtime/development dependency versions are pinned;
- rate-limit principals no longer retain raw API keys;
- Lambda packaging targets the deployed architecture explicitly;
- the DynamoDB physical name is environment-generated by default.

### Security

- removed application API keys from CloudFormation parameters and GitHub workflows;
- restricted OIDC trust to an exact repository/environment claim, with support for GitHub immutable owner/repository ID subjects;
- separated deployment and CloudFormation execution roles;
- forbidden anonymous access outside dev in the canonical deployment path;
- added production table deletion protection, secret retention, reviewed action release pins, and immutable release verification.

## 3.3.0-m1.2 — 2026-08-01

### Added

- tenant provisioning and tenant-scoped resource access;
- persistent projects with draft, active, and archived lifecycle states;
- optimistic-concurrency revisions for project updates;
- immutable, sequential analysis-version history;
- opaque cursor pagination for project and analysis lists;
- SQLite persistence with migration ledger and composite foreign keys;
- DynamoDB single-table adapter with transactions and conditional writes;
- encrypted, point-in-time-recoverable DynamoDB infrastructure;
- persistence health information;
- data-model documentation and persistence ADR;
- local database initialization command;
- tests covering cross-tenant isolation and both persistence adapters.

### Changed

- public contract version raised additively to `1.1.0`;
- application version raised to `3.3.0-m1.2`;
- analysis construction is shared between ephemeral and persisted workflows;
- runtime dependencies now explicitly include boto3;
- SAM Lambda policy is restricted to the application table.

### Security

- storage access always includes tenant scope;
- cross-tenant lookups conceal resource existence;
- the temporary header-based tenant context is documented as insufficient for public SaaS exposure.
